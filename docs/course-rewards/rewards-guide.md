# 课程奖励操作指南

## 进入课程与勋章设置

管理员或被明确授权的执行导师进入“课程管理→对应课程→课程奖励”，先核对课程名称/编号。普通教师无写入、工作人员无个人兑换资格。课程授权及学校建号见另附指南。

新课程默认关闭通关勋章。逐课时点“设置勋章”，填名称≤60字、描述≤500字，选复用图案或上传一张PNG/JPEG/WebP（≤5MB、≤1600万像素，建议透明像素图）。上传成功后仍须保存定义；“改用复用图案”只移除当前上传引用，不删除历史图。课时可单独停用；未完整可先保存草稿，学生不显示、不授予。

开启课程开关时明确确认适用于当前及以后满足原学习要求的学生。只有完整且启用的定义才按原回顾、卡片练习、最新报告与所有相关作品条件授予；参观无个人完成证据不空发章。学生进入/恢复页面执行原幂等补授，每人每课时唯一记录并留条件快照；反复开关/刷新不重复授予或播放已展示动画。弹窗可关闭/跳过，减少运动偏好保持。

关闭课程或课时勋章只停止新显示/授予，已有个人勋章保留名称、描述、图案、课程/课时及时间快照；不影响金币或礼品兑换徽章。

保存失败保留输入；409先“核对最新修订（保留输入）”，对照修改后再明确保存。上传失败可重试原文件。离开有未保存保护；权限撤销后清私有内容，仅本人键入文字可导出核对，重新授权后检查并重选文件。

## 礼品新增、真实上传和预览

“新增礼品”自动绑定当前courseId，服务器校验；跨课程复用新建独立礼品，不做共享库存或移动旧礼品。

|字段|规则|
|---|---|
|名称|必填1–80字|
|类型|实物/数字兑换徽章；有订单后不可改类型|
|介绍|≤2000字|
|图片|一张PNG/JPEG/WebP，≤5MB/1600万像素，上架必需|
|金币价格|1–1000000整数，账号统一真实金币|
|剩余库存|0–1000000整数；订单事务真实减少|
|每人限兑|留空不限或1–1000000整数，同一兑换徽章始终限一次|
|上架|保存生效，学生仍须有效报名且课程发布|

“学生效果预览”只预览、不兑换扣币。图片上传不等于保存礼品，改完点“保存礼品”。已兑换订单保留当时名称、说明、图片、价格、课程和学生快照。库存可能被并发兑换修改；409后核对最新修订和实际库存，不能用旧库存盲覆盖。失败保留表单和当前文件重试；保存中禁止修改和误离开。

学生“我的”保留账号统一余额、签到、墙与兑换，按课程筛选；课程内链接携带筛选。实物成功提示“兑换成功！老师会在下次课把奖品带给你哦~”，兑换章真实到账。结果不确定时用“重新核对这次兑换”，保留原请求编号，不另发新请求。事务内核余额、核库存、扣币减库存、建单/授章；通知失败不重做兑换。

## 发放、历史与通知恢复

“兑换管理”显示学生、礼品、消耗、时间和状态。实际线下发放后“标记已发放”，确认记录操作人/时间并通知学生；重复确认不重复发放记录或扣币。数字章自动到账。通知/工作台定位对应课程订单，旧深链可兼容跳转。

课程撤回/报名失效阻断新兑换，已有实物订单仍由admin/合法课程导师履约。学生跨设备保留本人订单状态、已获章、金币明细和历史图片；失效课程教材、未获章和可兑列表不能因此继续访问。导师撤销后列表、图案、上传及发放立即拒绝，管理员重新安排。

出现待发送通知时用“重试待发送通知”，只恢复本课程（或admin未归属区）真实奖励队列，含隔离失败事件；后台worker也会重试。收件人按当下有效管理关系解析。订单幂等与通知去重独立，不能用重新兑换补通知。

## 未知存量逐项绑定

1. 停相关写入，联合备份数据库/附件，私有保存只读清单：`node scripts/course-reward-audit.cjs --db <已有真实库>`。该工具不加载配置、不迁移、不绑定。
2. admin在课程管理“核对待关联课程的存量礼品/历史订单”核对原图、库存、价格、限兑、状态与原订单。不按名称、顺序、唯一课程或测试ID推测。
3. 每项点“核对并绑定课程”，明确选择真实目标、填依据，确认已备份。绑定有修订检查和审计；失败保留输入，冲突须重新核对。
4. 只补已确认礼品及缺失归属的订单/兑换章课程信息，已有courseId快照优先，不改金币、请求编号、订单快照、状态、库存。旧请求重放仍恢复原单。
5. 未确认旧礼品不开放学生新兑换；本人历史图片/订单和admin履约保留，导师不能看未归属。绑定后在目标课程维护，不可再次转移。

本地持久环境未导入合成奖励。截图测试礼品/1金币价格只用于验收，正式奖励由维护者录入；本轮未制定新奖励规则、重算金币、开发新AI、提交上游PR或部署公网。
