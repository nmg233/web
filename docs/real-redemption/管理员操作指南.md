# 真实礼品兑换：管理员操作指南

本轮只在本地持久环境运行，不切换公网。真实礼品默认空白，由管理员录入。截图中的「验收……（测试）」均来自独立数据库，不在教学环境上架。

## 进入与权限

管理员侧栏点击「奖励管理」，或进入 `/reward-management`。执行导师、教师、新媒体和学生不能维护奖励；直接调用管理接口也会被拒绝。强制改密、账号停用等原有规则继续生效。

## 新增与保存

1. 点击「新增礼品」，填写名称（1–80字）、实物／数字徽章及介绍（最多2000字）。
2. 选择一张PNG、JPEG或WebP图片，最多5MB、1600万像素。等待「图片已上传；保存礼品后生效」。不支持SVG、GIF或外部图片地址。
3. 填写金币价格（1–1000000整数）和**剩余库存**（0–1000000整数）。价格没有预设正式数值。
4. 填写每位学生**累计**限兑次数；留空表示实物不限次数，仍受库存和余额限制。同一个数字徽章每个账号只能获得一次，即使限兑栏留空或大于1。
5. 打开「上架」让学生可以兑换。上架必须有图片；库存为0时学生能看到但不能兑换。下架隐藏学生礼品列表条目，既有订单和徽章保留。
6. 可先点「学生效果预览」。使用当前表单及已上传图片，不创建订单、不扣币、不发徽章。
7. 点「保存礼品」，看到「礼品已保存到服务器」才算完成。重新进入或换设备仍能读取。

上传图片和保存礼品是两步。只上传、未保存表单，不改变学生展示。表单文字仅在当前页面内存中，没有服务器草稿；不要保存前刷新浏览器。关闭编辑时提示放弃尚未保存的修改。上传失败可以重新选择文件，原教学附件不受影响。

## 修改、库存及下架

点击条目的「编辑礼品」，修改后保存。库存填**当前剩余数量的绝对值**，不是本次补货数，例如剩2件、补5件，应填7。

另一管理员修改或学生已兑换导致库存变化时，保存提示「礼品或库存已变化」。先留存新文字，关闭后刷新列表，再编辑；不会覆盖新库存。有人兑换过的礼品不能更换类型，应另建礼品。

订单及徽章保留兑换当时的名称、介绍、图片与价格，不追扣金币、不更改历史快照。本轮没有删除礼品、退款、取消订单或撤销徽章入口。

## 兑换与线下发放

「兑换管理」显示学生姓名、账号及ID、礼品、消耗金币、兑换时间、状态，倒序分页，每页20条。实物兑换成功显示：

> 兑换成功！老师会在下次课把奖品带给你哦~

管理员通知中心收到兑换通知并跳转奖励管理。老师线下交付后找到订单，点「标记已发放」并确认；服务器记录操作人ID、姓名快照及时间，并通知学生。重复确认保留第一次操作记录，不再次扣币或扣库存。

数字徽章在兑换事务中直接加入账号徽章墙，订单显示「徽章已到账」，系统自动发放，无需管理员再标记。

## 学生入口与跨设备

「我的」保留真实金币、签到日历和明细，底部兑换实物；姓名旁「徽章墙」底部兑换徽章。详情显示价格、库存和限兑，确认后服务器核验扣币。

两处「兑换记录」显示当前账号全部真实订单。支出进入真实金币明细。另一设备登录同一账号可读取余额、订单、徽章、发放状态。礼品与记录在回焦、联网及每30秒刷新，也可手动刷新；金币沿用原有回焦与签到／学习核对流程。

确认期间价格变化会拒绝旧价格，需重新查看。金币不足、库存不足、达到限兑、已拥有徽章或下架时不扣币。

## 不确定结果与通知恢复

断网、超时或丢响应时保留原请求编号，提示「有一笔兑换结果待核对」。点「重新核对这次兑换」；刷新也能恢复。不要清理恢复信息后重新发起。原编号只返回原订单。

浏览器恢复信息只有请求编号、礼品ID、确认价格，按账号隔离；余额和订单仍以服务器为准。另一设备可先查兑换记录。

通知失败不撤销订单，也不要求重新兑换。待发通知持久保存，启动及每30秒重试。管理员看到待发送数量，可点「重试待发送通知」。检查接收账号与通知服务；恢复后同一通知只创建一次。通知延迟时发放状态仍可查看。

## 本地运行、备份与回滚

普通启动会增量迁移，不seed礼品。禁止 `db:reset`、`db:init --force` 或清空迁移记录。升级前备份：

```powershell
npm run teaching -- backup --to .local/teaching-before-your-upgrade
npm run build:teaching
npm run teaching -- start
```

默认地址 `http://127.0.0.1:4184`，API `http://127.0.0.1:3154/api`，私有配置保持不变。已启动时不要重复占用端口。

恢复写入**新的**目录，不能覆盖正在使用的数据：

```powershell
npm run teaching -- restore --from .local/teaching-before-your-upgrade --data .local/teaching-restored
```

先检查恢复目录端口再启动。真实订单产生后，不得让旧代码连接新库，否则旧版本不认识支出、可能展示错误余额。回滚须连同对应备份与上传文件恢复，并先保存升级后数据、核对新增教学记录与订单；恢复会回到备份时点。

数据库、私有配置、真实学生资料、上传图片及测试截图均未纳入Git。
