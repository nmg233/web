# 真实兑换接口与数据约定

接口前缀 `/api/reward-shop`，JWT及原强制改密检查，响应 `Cache-Control: no-store`。学生只能读自己的订单和徽章。管理写接口均限定当前有效管理员；库存／发放事务再次核验管理员身份。礼品图片通过鉴权接口读取，不公开整个上传目录。

|角色|方法及路径|作用|
|---|---|---|
|学生|GET /gifts|已上架礼品、库存／限兑提示与真实余额|
|学生|GET /orders?page=1|本人所有类型兑换记录，每页20条|
|学生|POST /orders|`{giftId,requestKey,expectedPrice}` 原子兑换；同键同内容返回原订单|
|管理员|GET、POST /management/gifts|列表、新增|
|管理员|PUT /management/gifts/:id|修改，须带读取时revision，库存变化即冲突|
|管理员|POST /management/images|multipart的image和requestKey，单张PNG/JPEG/WebP，5MB、1600万像素|
|管理员|GET /management/orders?page=1|所有兑换记录|
|管理员|POST /management/orders/:id/fulfill|空对象，线下发放确认，重复调用保留首次记录|
|管理员|GET /management/notifications|奖励待发通知数量|
|管理员|POST /management/notifications/retry|空对象，重试奖励队列，不重建订单|
|管理员／学生|GET /images/:id|管理员可预览；学生仅上架礼品或本人历史订单图片|

保存礼品字段：`name,type,description,imageId,price,stock,perStudentLimit,published`，更新额外带 `revision`。类型为physical／badge；限兑留空传null。价格／库存／限兑均为整数。库存是剩余数量绝对值；同一数字徽章每账号唯一。礼品不得通过未知字段注入学生、扣币或发放状态。

请求键与学生账号共同唯一；不同礼品或确认价格复用同键返回409。原请求未确认时浏览器只保存该键和礼品／价格，按账号隔离，不保存余额；重新核对同键。业务409需重新读取，网络错误保留请求键。跨设备以服务器订单为准。

原收入流水保持不变；订单cost承担支出，余额=原收入之和−订单cost之和。coin_activity提供两种明细的统一稳定游标，不通过修改原收入规则扣币。订单保存学生／礼品快照，发放保存操作人／时间；兑换徽章独立账号授予。

通知与订单同事务写入outbox，通知创建及投递标记另一个事务；进程启动、每30秒及管理员手动重试均可恢复，仅处理real-reward前缀。通知失败不重建兑换。图片上传与礼品保存分步完成，取消表单不自动删除已上传文件；本轮不增加资产清理或退款业务。
