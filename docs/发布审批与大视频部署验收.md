# 发布审批、课时暂停及 1.5GB 视频部署验收

本说明对应迁移 1035。仅交付代码和配置建议，不代表正式服务器已经更新。全量回归与目标环境门禁未通过前不得放行。

## 使用流程

1. 管理员在导师专属档案或课程维护的“课程管理授权”明确授予总课题权限。授课人不是授权来源；撤权下一次请求即生效，停用导师仍可撤销历史关系。
2. 导师创建总课题草稿，填写介绍和上线学校范围，提交管理员审批。管理员核对提交快照后批准，直接发布介绍；不强制先有正式课时，空课程不会自动结课。
3. 对应课时工作区填写草稿：课堂回顾可用真实正文／文章替代视频，正常课时必须有已发布卡片与完整配套题。参观课时只读，不计结课。
4. 提交该课时审批。管理员批准所提交版本后正式开放；提交后继续改稿会导致旧申请无法批准，须驳回并重新申请。导师和管理员均不能绕过审批直接将草稿设为正式版。
5. 修改正式课时先“关闭并编辑”。所有学生暂停学习、下载对应教材、播放新请求及提交；已有报告仍可由导师按原版本评审，退回后等待恢复再重提。保存草稿或驳回不会开放，批准才恢复。
6. 旧学生保留原教材版本、作答、成绩、一次答题机会、报告与历史；新开始学生使用新正式版。已结课结果不回退。未结课学生需学习新增正式非参观课时，新增草稿不计进度。

暂停操作不能收回已经下载到浏览器的字节。服务端立即拒绝后续学习／提交／媒体请求，已打开学习页每 15 秒及重新聚焦时检查状态并停止播放。离线状态、已下载资料和客户端缓存不属于远程可撤销内容。

## 1.5GB 的精确定义及资源预算

- 专用 MP4/WebM 单文件上限为 **1,500,000,000 字节**，不是 1.5GiB。普通资料仍为 50MiB，封面和反馈等不跟随放大。
- 前后端共用 `shared/uploadPolicy.json`。新上传请求进入指定课程、指定课时路径，先检查权限、课时状态，再接收文件；落库前再次核对归属和权限。
- 浏览器和 Node 请求体接收预算为两小时。单进程最多四个视频上传；磁盘可用空间必须覆盖已接收并发的最坏单文件预算及 256MiB 余量。多进程部署必须另配共享配额，不把单进程计数当作全机限流。
- 整文件上传保留取消、幂等和结果查询；没有分片、断点续传或转码。丢响应先查询结果再决定重传，不能宣称支持续传。

以下为 Nginx **专用回放上传路径**的示例，需人工合并到实际 HTTPS server，不覆盖整份配置：

```nginx
location ~ ^/api/courses/[0-9]+/(lessons/[0-9]+/)?replays$ {
    client_max_body_size 1536m; # 大于 1.5GB，留 multipart 开销
    client_body_timeout 120s;  # 读取间隔，不是上传总时长
    proxy_request_buffering off;
    proxy_http_version 1.1;
    proxy_send_timeout 120s;
    proxy_read_timeout 7200s;
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

其余 `/api/` 保留原上限、鉴权、日志及代理配置。若实际配置还有限流、访问控制或安全头，专用 location 必须保留同等策略，不能以此示例覆盖。关闭请求缓冲让 Node 尽早返回越权／空间不足，仍须核查实际 Nginx 临时目录容量。CDN、负载均衡、防火墙也要核对体积及超时上限。

## 发行目录与前端放行探针

`mktemp -d` 的 0700 根目录会让 Nginx worker 无法穿越，造成后端健康但首页 500。本轮脚本只开放发行根和 frontend 目录的遍历权限，公开 dist 目录及文件可读，不改变后端、环境文件、数据库及私有附件权限。

先核对实际 worker 用户以及当前 Nginx root，示例中的 nginx 不能直接假定适用所有主机：

```bash
sudo nginx -T
ps -eo user,args | grep 'nginx: worker process'
NGINX_USER=nginx FRONTEND_URL=https://你的实际域名/ \
  PYTHON=/usr/bin/python3.11 bash scripts/deploy-release.sh main
```

运行用户须能通过 `sudo -n -u "$NGINX_USER" test -r <发行目录>/frontend/dist/index.html` 做只读检查；权限不足时发布在切换前停止，不自动修改 sudoers 或父目录权限。发行根及父目录也须允许该 worker 遍历。

切换后除后端 SHA/schema 外，必须通过 Nginx 读取首页和构建引用的 JS/CSS，与本发行版逐文件哈希比对；旧首页、SPA 兜底、JS 404 或内容错版均不能放行。探针失败沿用安全停服与维护标记，不自动让旧代码使用已迁移数据库。

## 必做人工验收

1. 生产一致性数据库副本升级到 1035，检查 foreign_key_check、integrity_check、原账号／作答／报告／文件哈希，联合恢复验证。
2. 五角色 UI：总课题申请、驳回、改稿、审批、课时关闭、旧报告退回、恢复重提、导师撤权及跨课程深链。
3. 实际 1.5GB 边界、超限一个字节、长视频 Range、取消、断网、丢响应、并发和磁盘不足；检查临时文件清理及正式 Nginx/CDN。
4. Android/iOS、Safari/Firefox、键盘与慢网；实际 Linux 发行切换及前端故障回滚演练。

以上尚未执行的目标环境验收不能用本地小文件、模拟部署或单元测试替代。
