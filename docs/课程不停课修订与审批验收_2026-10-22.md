# 课时不停课修订与审批 · 2026-10-22

## 本轮范围与用户确认

取消“编辑前先关闭课时”。管理员和负责该总课题的执行导师可直接编辑正式课时、上传文件，保存到工作草稿；课时正式发布仍须管理员审批。审批期间学生继续学习、播放、下载和提交原正式版，导师可按学生绑定版本评审、退回，学生可继续修改重提。

| 情形 | 管理端 | 学生端 |
| --- | --- | --- |
| 新课时草稿 | 编辑、上传、提交审批 | 不展示，不计结课要求 |
| 正式课时开始修订 | 直接修改工作草稿，无须关闭 | 原正式版继续开放 |
| 新版本待审批或被驳回 | 草稿保留，可核对申请与修改记录 | 原正式版不受影响 |
| 管理员批准新版 | 审核提交快照，切换正式版本指针 | 新开始学生使用新版；已开始学生保留原绑定版 |
| 历史关闭课时升级 | 恢复其原正式版，工作草稿继续保留 | 恢复原正式版，不改作答、成绩、报告或结课结果 |
| 归档课程、取消课时 | 仍只读，不恢复写入能力 | 原归档／取消规则不变 |

总课题介绍发布后的修改仍按原确认规则直接保存，不另加审批。普通教师仍只读；未授权导师不能查看或编辑课程，也不能审批。角色和课程授权没有放宽。

## 实现边界

- 工作表继续承载草稿，`lessons.published_version_id` 指向学生使用的不可变正式快照。旧正式课时尚无正式指针时，迁移和首次编辑守卫先冻结原内容，再允许写入。
- 学习页、课程详情、任务列表、首页安排和待办、作品关联任务名称、资料／视频访问和学生 AI 课程来源统一遵循正式／绑定版本，避免从旁路泄露草稿。AI 不因此自动启用，不调用真实供应商进行验收。
- 卡片与习题继续按学生已绑定版本学习；不增加答题机会，不重判旧题，不覆盖参考答案、详解、成绩或报告历史。
- 独立成果任务不是课后学习必经阶段，继续保留独立入口和状态。其题目要求等定义纳入课时审批快照，审批前不可提前展示新增任务或提交；批准后使用最新正式任务定义，不因学生卡片绑定旧版而隐藏后续独立任务。已有作品与版本链保留。
- 保留提交快照、内容指纹、撤权检查与防重复处理。提交后继续改动教材，应由管理员驳回旧申请，导师核对现稿后重新提交；不能直接批准提交后发生的未审变更。
- 前端移除“关闭并编辑”操作，正式／历史正式课时不再因此禁用编辑、卡题或文件选择。旧关闭 API 返回有说明的 `410`，不会改变学生可用性。历史关闭事件仍可查看。
- 视频限制仍为 MP4/WebM、**1,500,000,000 字节（1.5GB）**。未扩大普通资料、作品、反馈和封面限制；文件签名、授权、归属、磁盘预算、版本引用保护仍有效。
- 原位教材编辑与受控预览侧栏不再提示“保存立即同步学生”，统一说明先存课时草稿、审批后生效。系统显示文案独立发布机制不变。

## 升级与兼容数据

在既有 1036 基线后增加命名扩展 `live-authoring-v1`，不抢占编号迁移，不改写原迁移文件。后端启动时随 `runMigrations` 执行，`schema_version` 仍可能显示 **1036**；不能仅靠该数字判定新代码已部署。

扩展新增 `lesson_authoring_recoveries`（恢复审计）与 `lesson_version_task_baselines`（旧快照任务兼容基线）。一次事务内冻结旧正式版、核对快照归属、恢复旧 `closed` 课时并记录扩展标记；重复启动不会重复恢复或覆盖后续正式指针。

不会把当前工作草稿当成旧正式版直接开放。若关闭课时缺少原正式指针、指针归属错误或快照损坏，则停止该扩展并回滚，要求核对备份；不要通过删除学习记录或强行设为 `published` 绕过。

旧系统没有为独立任务保存完整历史定义，无法凭空恢复曾被原地改写的题目要求。兼容基线使用升级时可取得的任务定义，原版本 JSON、作答、作品与成绩不改写；存量任务须在副本演练与业务签收中人工核对。新生成的提交快照完整记录任务定义，不再沿用这个缺口。

旧待审批申请本身保留。若其提交快照不含新版任务字段，前端提示管理员**驳回后重新提交完整教材**，服务端禁止漏审直接批准。驳回不丢失工作草稿、不关闭原正式版、不删除旧申请；已经批准的历史审批记录不改写。

部署前仍须对数据库、普通上传、私有上传及配置做联合备份，先在正式库一致性副本演练。代码、前端构建、后端进程必须为同一发布版本，切换后强制刷新旧页面；本轮未操作服务器或正式数据。

只读核验示例（在数据库副本上执行）：

```sql
SELECT name, applied_at FROM app_schema_extensions WHERE name='live-authoring-v1';
SELECT * FROM lesson_authoring_recoveries ORDER BY restored_at, lesson_id;
SELECT id, title, publication_state, published_version_id FROM lessons WHERE publication_state='closed';
PRAGMA integrity_check;
PRAGMA foreign_key_check;
```

恢复审计同时展示在课时审批面板的历史记录中。升级成功后不应仍有旧关闭课时；发现异常应停止放行并查日志，不手改正式库。
