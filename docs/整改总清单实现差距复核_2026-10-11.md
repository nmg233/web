## 2. 明确仍需整改或完善的项目

### U-01：执行导师教学编辑权限与已确认需求不符

关联：Q-01、D-03～D-07、M04。

当前前端内容编辑路由仅允许 admin；创建、修改、删除卡片/习题及排序 API 仅允许 admin；learningService 的写入检查也只允许 admin。导师内容查询会隐藏参考答案和详解，课程详情仅管理员看到编辑按钮。不能只加一个前端入口就称为修复。

证据：`frontend/src/App.jsx`、`backend/routes/learning.js`、`backend/services/learningService.js` 的 assertWritableLesson/listManagedCards、`frontend/src/pages/courses/Detail.jsx`。

用户于本次复核明确确认：**恢复原规则，负责该课程的执行导师和管理员可编辑，普通教师只读。** 本轮尚未实施。后续需同时调整入口、路由、API、服务对象权限和可编辑者的答案 DTO；回归无关导师 403、普通教师只读及管理员专属兼容修复边界。

### U-02：课时和任务维护仍未形成前端操作闭环

关联：第四轮 F2-05/F2-06、首轮 R10、M03/M06。

后端有课时编辑/取消、任务编辑/取消接口，但 frontend/src/api/index.js 未封装对应操作。课程详情只有添加课时、添加任务等入口；任务详情没有管理者编辑/取消操作。用户无法仅通过界面完成时间、地点、负责人、任务要求的修正及取消管理。

需要交付：管理入口、确认/原因、明确的保护失败提示、取消后待办/统计同步及历史查看；不能只证明后端 API 可调用。

### U-03：资料维护和归属更正不完整

关联：D-07、R-08、第四轮 F2-07。

资料创建可设置 lesson_id，下载和后端删除已存在，但课程资源列表没有删除按钮；也未提供资料元数据/课时归属修改接口和表单。误绑后不能从页面更正。列表仅展示类型、标题、下载，公共/指定课时归属不清晰。

证据：`backend/routes/courses.js`、courseController.uploadResource/deleteResource、课程详情 resources 页签。

维护必须保持历史快照引用保护；不能以删除再上传绕过历史保护。

### U-04：教师逐学生列表只完成了部分 D-01

列表已有学校/班级/课程/状态筛选、分页和返回筛选，但列只有近 30 天完成、学习中课时及关注标签。没有直接展示课程进度、当前课时/阶段、待提交/待评审情况；后端返回 last_learning_at，前端未展示。

证据：`frontend/src/pages/observer/StudentList.jsx`、`backend/services/observerService.js`。

因此“能进入详情”不能替代文档约定的进度列表。多门课程应有明确展示方式，不能任意选择一门伪装为学生全部进度。

### U-05：课程筛选与学习状态筛选不是同一课程口径【本轮隔离复现】

course_id 只限制学生报名了该课程，而 completed/learning/not_started/revision 条件查学生所有课程。

复现：学生在 A 课未开始、B 课已结课。选择 A 课 + 已结课，仍返回该学生；选择 A 课 + 尚未开始，又因 B 课有版本绑定将其排除。

证据：observerService.students 中 course_id 条件与 statusSql。

后续需明确：不选课程时保持学生全局多课程口径；选定课程时状态与统计限定相同课程，并覆盖待修改及未开放情形。

### U-06：已结课后的课时完成数与百分比矛盾【本轮隔离复现】

课程百分比读取冻结的结课清单，完成数/总数却对当前全部未取消课时计数。

复现：学生结课时仅要求一课时，之后新增一课时。教师详情同一课程显示 1/2 已完成、100%；completion.lesson_ids 仍只有原课时。

证据：observerService.studentDetail 中 courses 聚合与 versions.courseState。

必须按“已结课保留结果”的确认规则统一分子、分母、结课时间和课时入口；新增课时如可额外预览，应明确为不影响原结课的补充内容。

### U-07：取消课时仍计入教师“学习中”统计【本轮隔离复现】

pending_lessons 虽 JOIN lessons，却未排除 cancelled。学生只有一条取消课时的 25% 进度，仍返回 pending_lessons=1；dashboard 据此计算学习中学生。两个取消记录还可能触发“连续课时未完成”关注标签。

证据：observerService.students/dashboard。

需统一有效课程/课时和历史记录口径，排除已关闭任务造成的伪待办。已完成历史统计是否保留应区别于当前可执行待办，不能一律删除历史统计。

### U-08：教师课时详情未完整交付 D-02

已有阶段、卡片作答数量和客观题汇总分，但未显示报告评分、报告版本、明确结课状态及时间。后端课时查询没有 SELECT r.score；report_version/ reviewed_at 虽返回也未展示。课程 completion.completed_at 已返回但前端没有显示。

成长档案另有报告评分，不代表教师当前学情页已经具备同样能力。需要在只读范围内补齐查看路径，并保持历史与最新版本区别。

证据：observerService.studentDetail、`frontend/src/pages/observer/StudentDetail.jsx`。

### U-09：兼容补学后的课后任务状态仍读旧报告【本轮隔离复现】

关联：N-03、R-35/R-36、Q-26。

统一学习状态已把存在 report_replacements 的旧报告解释为需修改，但 taskController.list 仍直接读取报告原始 status。

复现：旧 submitted 报告被标记要求补学重提，实际学习状态为 rejected、进度 25%；课后任务列表仍返回 submitted/待导师评审。若旧报告为 approved，taskStatusFromLearning 的 approved 分支也可能造成已完成展示（此组合本轮源码确认，未额外复现）。

需让学习总界面、任务筛选、按钮、教师观察与评审队列共用有效状态，不只修一个页面。

### U-10：登录刷新仍提前相信缓存身份

关联：第四轮 F3-02、首轮 R15。

AuthContext 从 localStorage setUser 后发起 /me，但在等待响应前执行 setLoading(false)。因此旧角色/强制改密状态可能短暂参与页面导航和渲染。后端权限保护不等于前端不存在身份闪现或错误跳转。

证据：`frontend/src/store/AuthContext.jsx`。本轮源码确认，未重新浏览器复现。

需等待身份校验，并区分网络失败与凭据失效；同时检查刷新操作与注销、重新登录之间的迟响应隔离。

### U-11：视频恢复只在部分播放器实现

关联：R-29、G-03。

课程详情回放区仍是普通 video src=replayUrl：playReplay 只取一次签名；没有学习页同等的自动续签、播放位置恢复和明确错误恢复。不能因为 LessonLearn 做了续签就把 R-29 所有入口关闭。

证据：课程详情 playReplay 和 replays 页签。真实长播放在本轮仍未验收。

需覆盖课程详情、学生学习及仍保留的旧学习入口，并验证签名过期/Range/权限撤销；不无限重试绕过撤权。

### U-12：大视频上传缺取消及完整结果恢复体验

关联：R-28。

已经有长超时、进度和请求幂等，不能说未做。但没有 AbortController/signal 的取消链路；关闭上传弹窗只 setReplayModal(false)，请求继续。重新开窗会清空 replayRequest 的键，上传中表单和文件选择也未统一锁定。

后端按请求键去重，不等于重新开窗后采用新键的请求也代表同一次操作。关闭、取消、超时、重开和确认最终结果需要分别设计及验证。实际重复生成场景本轮未执行，不将风险写成已复现故障。

证据：courseAPI.uploadReplay、课程详情 openReplayModal/handleReplaySubmit 与上传 Modal。

### U-13：返回上下文与列表请求隔离仍不完整

关联：M02、D-08、G-07。

- 评审列表 status/page 在本地 state，详情固定返回 /mentor/reviews，返回会重置待评状态和第一页。
- ReviewList.load 没有请求序号/取消检查，快速切换状态时旧响应仍可能覆盖新筛选结果（源码确认，未浏览器复现）。
- 教师学生列表已保存筛选，但从学生详情进入课时预览后，预览固定返回未带筛选的学生列表，丢失该学生及列表上下文。

证据：mentor/ReviewList.jsx、mentor/ReviewDetail.jsx、learning/LessonPreview.jsx、observer/StudentDetail.jsx。不能把部分详情防乱序等同于全站导航闭环。

### U-14：简答题专用“评价要点”未实现

关联：D-03。

现有简答表单支持参考答案和详解，提交即完成的规则已实现；但文档另列的评价要点无专用表单/数据字段。若用详解兼任，要明确字段语义和导师呈现，不能声称独立评价要点已经交付。

证据：QuestionFields.jsx、questionForm.js、card_exercises 的数据结构。

### U-15：手机端和全站 UI 重构仍是局部实现

关联：第四轮 F3-03/F3-05、旧 R06、10 月 8 日必交 UI/手机范围。

新学习/评审页有响应式网格和部分触控适配；全站仍使用小屏 64px 固定图标侧栏，不是约定 Header+Drawer。Header 仍是单行固定空间，没有独立移动重排。学生课程列表仍是管理型横向表格，非计划课程卡片。

本轮未重新测量小屏溢出，不能照抄 9 月 25 日尺寸作为当前实测值，也不能据有限 CSS 就判真机通过。需要五角色 320～430px 核心任务、Android/iOS、软键盘、横竖屏及键盘/焦点验收。

证据：Sidebar.jsx、Header.jsx、courses/List.jsx、index.css。

### U-16：术语及字段展示仍未统一

顶部和用户管理仍显示“学术导师”，文档及产品角色称“执行导师”；课程列表直接展示 primary/basic 等原字段，课程详情虽已中文映射，列表未同步。

证据：Header.jsx、students/List.jsx、courses/List.jsx。改接口内部 academic_mentor 标识不是必需操作，优先统一用户可见字典。
