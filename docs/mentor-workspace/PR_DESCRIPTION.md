# PR 标题

feat: 完善导师办课、学校与教师隔离、课程反馈及主题课程包

# PR 描述

本次让外部执行导师可以在获准学校内完成建班、建号、备课、上线课程、处理学生反馈的完整流程，并补齐管理员的授权、协作和兜底处理。基于已合并的管理员整理 PR #47，保留既有学习、教材历史、作品/报告评审、真实金币与课程奖励规则。

## 导师功能

导师侧栏归并为工作台、课程管理、教学与成长、学校与账号、使用指引。工作台集中显示所管课程、待评审、待发放、课程反馈和申请回复，保留菜单图标、折叠、键盘和手机操作。

- 可直接创建课程草稿，在获批学校范围内明确选择上线学校；学生仍需有效报名，不会自动全校选课。
- 在获准学校建班、建立student和teacher账号；学生账号仅本人创建或管理员明确委托的范围可维护，同校不自动取得全校账号或学习数据。
- 沿用课程六页签及学生同源编辑、真实上传和版本保护；新增报名/招生同时核验课程管理、学校范围及学生账号来源。
- teacher按“教师×学生×课程”明确授权只读观察，新增课程不自动扩权；学校、课程、账号委托撤销和教师迁校持续校验。报名已移除时可撤销既有观察授权，再交接迁校，保留原记录与审计。

## 重点：哪些无需逐次审批，哪些仍由管理员批准

**创建新课程是mentor现有的直接权限，不走“既有课程管理申请”。**导师可先建草稿、填教材、建课时并使用四套公共主题；尚无获准学校时也可以备课，但不能发布上线或新增招生。课程管理申请用于申请参与管理别人已经建立的课程。

|操作|是否需要管理员另行批准/授予|
|---|---|
|创建自己的课程草稿、编辑课时、上传教材、预览和受控数据课程包导入|无需逐课批准；须在自己的有效课程管理范围内，导入不自动发布|
|选择课程上线学校、发布课程|已有学校管理授权后可直接操作；仅能选择自己获准管理的学校，不需每次发布重新申请；没有学校授权不能上线|
|本校建班、创建student/teacher、为有权维护的学生报名、配置合法teacher观察关系|学校授权及相应课程/账号范围具备后可直接操作，不逐个账号申请；不自动取得同校他人账号或教学记录|
|申请新学校或取得现有学校管理权|必须由管理员单独审核；回复申请消息不等于批准|
|管理非本人创建的既有学生账号|必须由管理员明确委托；仅同校、仅获得课程权均不够|
|配置他人创建的teacher、调整他人建立的观察关系|由管理员处理；mentor仅可配置本人创建的teacher和本人建立的合法观察关系。学生账号委托不会转移teacher管理权，本轮没有通用的teacher接管委托入口|
|加入管理别人的课程、给其他mentor授予/撤销课程管理权|必须由管理员批准/操作；mentor不能再授权其他mentor|
|缩小课程学校范围且影响现有有效报名|必须管理员明确核对、确认保留既有报名；mentor不能自行绕过或静默删除历史|
|开发方案资格|必须管理员按mentor×课程单独授予，可设期限/撤销；申请审核通过与实际资格授予分别处理，且两者均不开放代码执行|
|创建mentor/admin、提升账号角色、全平台账号/配置、服务器脚本与数据库变更|不属于mentor权限；由管理员及服务器负责人按审核流程处理|

学校管理权、课程管理权与学生账号委托分别校验：批准一所学校不会让mentor管理该校所有课程；授权一门课程也不会同时授予学校办学或全校学生账号管理权。

普通教学上传、四主题选择和受控数据课程包导入，不要求先取得“自主开发方案资格”。该资格不能替代课程管理权或学校管理权，也不能授权执行SQL、任意代码或服务器命令。

## 课程绑定学校后，谁能使用

新课程按明确绑定的上线学校招生，mentor只能使用自己获准学校的范围。可以选择一所或多所自己获准管理的学校；绑定甲校不会把课程自动开放给乙校。

- 学生：属于绑定学校只是招生条件，还必须由有权管理的工作人员为该学生建立有效报名，且课程已发布；同校或同班不会自动获得入口，也不自动看到其他学生的答案、报告或作品。
- 班级：用于组织学生，不等于整班自动选课。当前以学校作为上线范围、以个人报名作为学习授权；如需“只开放某几个班级”，应只给目标班级学生报名，本轮没有独立的班级上线白名单。
- teacher：创建本校账号后仍不会自动看到本校课程。只通过观察入口，按明确授予的“教师×学生×课程”范围只读查看；不等同学生的学习入口，没有编辑、评分或发放权限。
- 管理人员：管理员保留全平台管理，当前课程的有效管理mentor保留课程管理与预览权限；学校权与课程权各自校验，不因同校自动取得别人课程的管理权。

**兼容边界须单列：**存量合法报名、迁移时冻结的旧教师关系及管理员明确保留的历史访问不会因升级被直接删除，不能把新招生规则描述成强制清退所有跨校历史。新媒体角色原有的已发布课程概览浏览也保留，不等于获得学生学习、教材回放或个人学习数据权限。因此本轮保证教学招生和观察范围隔离，不宣称所有角色、所有历史关系均按学校绝对封闭。

## 管理员新增与强化的功能

管理员保留上一轮五模块，并具备本轮导师的全部合法操作；不是另开一套管理系统。

|位置|本轮变化|
|---|---|
|工作台|汇总当前由管理员受理的课程/平台反馈及导师转交问题、待审核申请及需要回复的消息，显示总数、完整列表和刷新状态，直达具体对象|
|账号与组织|审核学校申请并往返回复；维护获准学校的班级/学生/教师；明确委托、撤销导师的学生账号维护范围；配置教师三元观察授权，保留旧教师冻结范围和交接审计|
|课程管理|逐课设置上线学校，缩小范围时核对已有报名影响；保留课程管理授权；查看并审核课程管理申请；操作同一课程包导入和学生预览|
|反馈处理|查看全平台反馈；接管导师转交问题、直接回复学生、要求补充或附原因转回有效导师；公开对话与内部协作分开|
|申请与开发方案|学校、课程管理和开发方案申请支持说明/附件/追问；审核和聊天分开。可授予、到期或撤销指定导师×课程的开发方案资格，记录真实操作者与审计；本版本不开放代码运行|

课程管理授权与学校管理权继续独立，导师不能再授权其他导师。普通teacher不获得编辑、评分、发币或履约权限，管理员直接操作也记录真实admin身份。

## 学生反馈与申请协作

有效课程反馈优先进入当前课程导师共同池，导师领取后可直接回复，必要时附原因和材料提交管理员协助。管理员可接管或转回，沿用同一反馈编号和历史；无课程、平台问题、旧反馈或无人接续时由管理员兜底。

学生只见本人公开对话，不能看到内部原因或附件。导师仅在学生允许联系时取得联系方式。受理变化、回复、申请补充和审核结果写入持久通知流程，通知已读不会清掉尚未完成的业务待办，撤权后旧链接和补投也重验权限。

## 四主题与受控课程包

- 新课程可选校园、蓝天白云、森林、海滩；新增24件独立像素素材母版、60个发布尺寸。每主题提供三枚可替换默认关卡，主题与四种课时模板分别配置。
- 存量星海远航主题和自上传素材继续保留，不能作为新课程直接选择/复制/导入的公共预设。平台外层仍使用北航校园风格。
- 课程内可配置地图、实验室、成长档案的标题/介绍/顺序及空实验入口隐藏；不替换核心学习组件或完成规则。
- 数据课程包经网页校验、预览、写入清单和确认后，新建草稿或向指定课程追加课时。支持暂存/结果查询、版本与请求去重、权限复核和失败补偿；不覆盖旧教材、历史答案或人工改稿，不自动发布、报名或发奖励。

**兼容边界：**v1包支持已声明的结构化教材、PNG/JPG/WebP图片及UTF-8 TXT/MD/CSV。拒收所有PDF（包括正常PDF）、Office、HTML/JS、SQL、CSS/字体和可执行模块；视频经原入口单独补传。不能上传脚本让主服务器执行。开发资格只用于准备/提交方案，交互代码运行环境尚未实现。

## 服务器数据库如何升级

**本轮有数据库结构变更，但没有要求重新导入现有课程或整库。**新增迁移为：

|编号|新增结构及自动兼容处理|
|---|---|
|1032 `mentor_school_scope`|课程上线学校、学生账号委托、教师观察与审计。按既有报名ID保留原访问，按原teacher_id与既有报名课程冻结历史观察；不会推断全校招生权限。学校管理权与新账号委托由管理员批准/授予；导师在已获准学校内自行选择课程上线范围|

最后两次补修没有新增迁移，不代表整个PR无需升级数据库。目标已到1034时不重复执行；目标比1031更旧时还可能需要前置迁移及旧编号桥接，必须核对完整`version/name`，不能只看最大编号、手改迁移记录或删除旧文件。

服务器负责人操作顺序：

1. 核对正式部署版本、数据库及上传/反馈附件的真实路径；取得匹配的完整新代码和依赖，但先不启动新后端。
2. 停止全部业务写入，联合备份数据库、上传/反馈附件，另行私有保存环境变量、JWT/AI密钥及服务配置；先在隔离副本演练。
3. 使用现有迁移工具列出pending，再在副本执行、核对完整性/外键和原教材/账号/报名/钱包/订单；无误后才在维护窗口迁移目标库。

```text
node scripts/lesson-maintenance/schema.cjs --db "<数据库绝对路径>" --dry-run
node scripts/lesson-maintenance/schema.cjs --db "<数据库绝对路径>" --uploads "<上传目录绝对路径>" --feedback "<反馈附件目录绝对路径>" --backup-dir "<全新私有备份目录>" --apply --maintenance-confirmed
```

4. 前后端发布同一审核提交，核对health就绪/schema1034，再验证管理员、导师、教师、学生和原教学/奖励闭环。
5. 管理员逐课确认上线学校，按需配置账号委托和教师观察范围。现有教材、学生、积分、徽章、礼品、订单不用重导；四主题图片随前端部署，不导入数据库。本地验收库、账号、样课和测试样包均不作为生产数据。

**注意：新后端加载数据库配置就会自动迁移，不能先启动试错再备份。**`--maintenance-confirmed`只代表操作者确认，脚本不会自动停止其他进程；dry-run只是清单，不等于升级演练。现有工具的`codeReference`旧提示不是实际代码版本依据。详细命令、只读预检及人工配置清单已纳入仓库`docs/mentor-workspace/server-handoff/`，部署入口为其中的`README.md`和`部署步骤.md`；迁移实际执行仍复用完整代码的`scripts/lesson-maintenance/`工具。

升级预期保留原数据，但需正式库副本演练，不能承诺零风险。回退时先停写并保全升级后新产生的数据；联合恢复到新目录并配套原代码，不清库、不删迁移行，也不能直接回旧库丢失新订单/教材。新版本临时课程包的异地暂存恢复不是完整支持项，成功导入的课程与未确认暂存分别处理。
