# 受理、通知和迁移边界

|情形|处理|学生可见|
|---|---|---|
|新有效课程反馈|当前有效课程mentor共同池，显式领取|公开对话、真实受理方|
|平台/无课程/旧反馈|管理员|自己的公开历史|
|转交管理员|内部原因、可带内部附件，业务状态不改|简短公开受理说明|
|管理员转回|必须当前有效课程mentor及原因|公开受理说明|
|撤权/停用/撤课/报名移除|当前权限即刻拒绝；无人接续管理员兜底|自己的反馈仍可跟进，无教材权限恢复|
|申请追问/补充|独立会话，不覆盖原文、不授权|仅申请导师与admin|
|批准/驳回|独立审核及版本检查|实际结果；开发方案不开放执行|

1033是新增迁移，保留上游编号、已有1032学校/观察范围、真实教学及奖励数据。feedback新增可空课程/学校、受理层级、处理人、修订与补充标记；旧反馈默认admin，不根据路径推断。新增受理审计、课程/开发申请领域表、公共申请会话/消息/附件；既有学校申请回填created_by和会话，原文/reason保留。学校申请触发器只为新行建立会话。

通知事件与业务同一事务落盘到现有outbox，入队失败回滚业务；投递失败保留错误、重试/隔离记录，管理员可从原通知投递管理重放。补投按当前负责关系/当前有效管理员解析，通知列表、详情、旧收件的动作都重新核验对象读取资格。私有内部说明不放进学生通知。

升级前联合备份SQLite、uploads、feedback、私有配置；停止仅待升级副本写入后运行现有迁移工具，readiness要求1033。重复运行不重复列/会话，不能重建库或清空迁移记录。恢复用联合备份到新目录验证后指回，不把1033列硬删。原4185/4186继续旧服务；独立新版4187在最终第三步后更新，迁移和部署步骤随最终交接完善。本轮不操作正式站。
