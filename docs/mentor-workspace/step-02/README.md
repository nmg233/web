基于第一步提交7b6ceab继续。真实接口与SQLite持久化；没有演示回复或自动审批，没有开启AI。第三步主题、包导入和资格配置在下一独立提交交付。

## 学生、导师与管理员操作

学生从课程侧栏“本课程反馈”进入会预选真实课程；帮助与反馈→提交反馈也可选择本人当前有效课程。课程问题交当前有效课程导师共同池；平台、账号和导师相关问题选择直接交管理员。课程失效可用平台反馈，不通过反馈恢复教材访问。

导师：教学与成长→课程反馈→具体反馈→领取→公开回复。公开回复可带3个附件，最多各10MiB，PNG/JPG/WebP/PDF。处理结果与待补充、解决等业务状态仍沿原规则；学生可补充、确认和重新打开。需要协助时选择“提交管理员协助”，填写内部原因，可附材料；保留同一编号与历史，不自动解决。

管理员：平台反馈管理/工作台通知进入原反馈，可直接公开回复、接管、要求导师补充，或写理由转回当前有效导师。转交后导师仍在授权范围内可读及加内部备注，不能并行覆盖管理员处理结论。学生不见内部原因、备注及其附件。老师teacher没有处理权限。

学校与账号→申请与回复，可提交学校、准确课程ID的管理申请、开发方案三类申请。原文与往返消息、附件分别保留。管理员可追问、申请者补充；只有单独批准动作才授学校或课程管理权。学校同名须核对确认；管理员代办选择真实申请导师，审计记录实际管理员。开发方案本步只讨论，不运行代码；第三步增加独立资格管理。

## 保存与恢复

草稿文字和待上传附件仅留本账号本对象当前标签页内存，尚未保存；刷新/关闭会丢失。离开有提示，保存中不允许离开。请求错误保留输入，409需先重新核对；提交使用请求键和修订号，重试不重复写消息。服务端已确认写入后才清输入；独立回读失败提示刷新，不重发。

反馈和申请会话均使用真实编号，通知直达具体对象。通知已读、隐藏不改变业务待办。双端工作台有完整总量、分类分页、最后更新时间、手动/聚焦/30秒刷新；完整申请列表保留已处理记录。
