# 要迁移什么，哪些不需要导入

## 1. 自动结构迁移和兼容回填

|迁移|变化|旧数据如何处理|
|---|---|---|
|1032|courses学校修订；课程学校范围；报名访问确认；组织账号委托；教师三元观察/历史目录、建教师及审计|只为已有报名ID建立兼容记录；按原teacher_id和原报名课程冻结历史观察。不会给全校开放新招生，不更改课时/教材/余额。课程学校范围和新账号委托初始不猜测填入|
|1033|反馈课程/学校/受理/修订字段；受理审计；课程/开发申请、申请会话/消息/附件|旧反馈默认管理员受理；学校申请created_by由applicant_id回填并建立原状态对应会话。保留原说明和审核理由，不猜旧反馈属于哪个课程，不把审核理由伪装成新消息|
|1034|courses可空public_theme；课程模块、开发方案资格/审计、课程包暂存/导入/待补媒体|旧campus/voyage、已上传图片、教材不批量重写。新表没有测试业务种子；没有自动创建样课/奖励/开发资格|

这些由完整代码的版本化迁移器执行一次。`schema_migrations`已经有正确同号记录的迁移不重跑；同号不同name、未知前置或老编号桥接先停下核对。若服务器比1031更旧，pending会多于三条，要把全部前置纳入演练，不能只复制本包三份SQL。

## 2. 不需要导入、也不能被覆盖的现有数据

既有课程/课时/卡片/教材快照、账号与报名、作品/报告/反思/评审、金币/签到/徽章、礼品/库存/订单和通知均保留，不要求把本地数据重新导入服务器。不重算/重发历史奖励、不重建课时、不reset/seed、不导入验收账号或测试礼品。

24件母版及60个发布尺寸是前端静态资源；随对应代码/构建部署，并核对发布目录包含资源。不要把原课程图案整体换成新主题，不把图片当数据库导入包。

## 3. 升级后的授权审批与日常配置

学校管理权、他人学生账号委托、既有课程的额外管理者及开发方案资格由管理员批准/授予；mentor创建自己的课程草稿无需逐课批准。已有学校授权后，mentor可在获准学校内自行选择课程上线范围并发布，不要求管理员每次重新批准。详见《权限批准与课程隔离说明.md》。

1. 逐课程核对上线学校。已有报名按具体记录兼容保留；新增招生前必须明确学校范围，不能从一个旧学生推断全校权限。
2. 核对mentor的课程管理与获批学校关系。旧关系若不完整，管理员在平台明确授权，不用改SQL或创建重复学校。
3. 按需委托已有学生账号给mentor维护；同校不会自动开放全校账号。新建账号走正式界面及强制改密，不导入本地凭据。
4. 按需明确teacher×student×course观察范围；历史teacher_id不自动扩大到新课程。移除报名后需要清理时，从既有授权行撤销，再交接/迁校。
5. 旧反馈继续管理员处理；新课程反馈自动按当前真实课程关系受理，不能批量从历史URL猜归属。
6. 公共主题只在需要时逐课选择/替换；原星海远航保留。开发方案资格由管理员按导师×课程审核，授予也不开放代码运行。
7. 如前置1031奖励课程归属尚未核对，按原奖励迁移指南处理，不在本轮脚本里猜礼品归属。

## 4. 可选的新教材录入

部署后可以用课程管理的原位填写/上传，或v1数据课程包网页导入。课程包默认新建草稿/追加新课时，不覆盖旧教材；导入后还需核对学校/报名、课时就绪、卡片发布和课程发布。

v1支持受控结构化教材、PNG/JPG/WebP与UTF-8 TXT/MD/CSV；所有PDF、Office、网页/脚本/SQL均拒收。大视频在原视频入口补传。用可信工具把Office/PDF转换为支持的文字与图片，或人工核对后在原课时资料入口单独补传。测试样包仅供隔离演练，不能当正式教材发布。

## 5. 迁移前后核验

冻结写入时，用预检脚本保留迁移记录、全部既有用户表（排除schema_migrations与SQLite内部表）的计数和原列哈希，副本升级后与迁移前摘要对照。已登记1031的库另检查脚本列出的25张核心表存在；这不替代完整结构及业务验收。新列默认值/兼容新表是预期新增，不能只比较数据库文件哈希；旧列内容变化、丢行或附件缺失均须解释。

脚本不证明所有业务语义正确。还要抽查真实旧课、25张卡片等原有具体内容、历史教材版本、文件可读、报名、原余额和订单；测试账号只用明确授权的隔离账号，不让真实学生承担验收。
