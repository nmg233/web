# mentor权限批准与课程隔离说明

按6271ba4代码核对；本文件仅说明现有规则，不新增权限、不改教学数据。与本次PR描述同步。

## 重点：哪些无需逐次审批，哪些仍由管理员批准

**创建新课程是mentor现有的直接权限，不走“既有课程管理申请”。**导师可先建草稿、填教材、建课时并使用四套公共主题；尚无获准学校时也可以备课，但不能发布上线或新增招生。课程管理申请用于申请参与管理别人已经建立的课程。

|操作|是否需要管理员另行批准/授予|
|---|---|
|创建自己的课程草稿、编辑课时、上传教材、预览和受控数据课程包导入|无需逐课批准；须在自己的有效课程管理范围内，导入不自动发布|
|选择课程上线学校、发布课程|已有学校管理授权后可直接操作；仅能选择自己获准管理的学校，不需每次发布重新申请；没有学校授权不能上线|
|本校建班、创建student/teacher、为有权维护的学生报名、配置合法teacher观察关系|学校授权及相应课程/账号范围具备后可直接操作，不逐个账号申请；不自动取得同校他人账号或教学记录|
|申请新学校或取得现有学校管理权|必须由管理员单独审核；回复申请消息不等于批准|
|管理非本人创建的既有学生账号|必须由管理员明确委托；仅同校、仅获得课程权均不够|
|配置他人创建的teacher、调整他人建立的观察关系|由管理员处理；mentor仅可配置本人创建的teacher和本人建立的合法观察关系。学生账号委托不会转移teacher管理权，本轮没有通用的teacher接管委托入口|
|加入管理别人的课程、给其他mentor授予/撤销课程管理权|必须由管理员批准/操作；mentor不能再授权其他mentor|
|缩小课程学校范围且影响现有有效报名|必须管理员明确核对、确认保留既有报名；mentor不能自行绕过或静默删除历史|
|开发方案资格|必须管理员按mentor×课程单独授予，可设期限/撤销；申请审核通过与实际资格授予分别处理，且两者均不开放代码执行|
|创建mentor/admin、提升账号角色、全平台账号/配置、服务器脚本与数据库变更|不属于mentor权限；由管理员及服务器负责人按审核流程处理|

学校管理权、课程管理权与学生账号委托分别校验：批准一所学校不会让mentor管理该校所有课程；授权一门课程也不会同时授予学校办学或全校学生账号管理权。

普通教学上传、四主题选择和受控数据课程包导入，不要求先取得“自主开发方案资格”。该资格不能替代课程管理权或学校管理权，也不能授权执行SQL、任意代码或服务器命令。

## 课程绑定学校后，谁能使用

新课程按明确绑定的上线学校招生，mentor只能使用自己获准学校的范围。可以选择一所或多所自己获准管理的学校；绑定甲校不会把课程自动开放给乙校。

- 学生：属于绑定学校只是招生条件，还必须由有权管理的工作人员为该学生建立有效报名，且课程已发布；同校或同班不会自动获得入口，也不自动看到其他学生的答案、报告或作品。
- 班级：用于组织学生，不等于整班自动选课。当前以学校作为上线范围、以个人报名作为学习授权；如需“只开放某几个班级”，应只给目标班级学生报名，本轮没有独立的班级上线白名单。
- teacher：创建本校账号后仍不会自动看到本校课程。只通过观察入口，按明确授予的“教师×学生×课程”范围只读查看；不等同学生的学习入口，没有编辑、评分或发放权限。
- 管理人员：管理员保留全平台管理，当前课程的有效管理mentor保留课程管理与预览权限；学校权与课程权各自校验，不因同校自动取得别人课程的管理权。

**兼容边界须单列：**存量合法报名、迁移时冻结的旧教师关系及管理员明确保留的历史访问不会因升级被直接删除，不能把新招生规则描述成强制清退所有跨校历史。新媒体角色原有的已发布课程概览浏览也保留，不等于获得学生学习、教材回放或个人学习数据权限。因此本轮保证教学招生和观察范围隔离，不宣称所有角色、所有历史关系均按学校绝对封闭。
