## 要交给服务器管理员什么

服务器可从审核后的完整代码取得本目录，或接收同版交接包ZIP及PR链接。服务器部署须使用审核后的完整代码，不只传三份SQL或主题图片。先读《部署步骤.md》，再操作。

|文件|用途|
|---|---|
|`部署步骤.md`|停写、备份、隔离演练、迁移、发布、核验和恢复限制|
|`数据与人工配置清单.md`|解释自动迁移、原数据保持、什么必须管理员配置及什么禁止导入|
|`权限批准与课程隔离说明.md`|区分mentor直接操作、管理员审批及学校/班级/报名/教师观察边界|
|`scripts/preflight.cjs`|只读检查迁移身份、完整性及既有用户表的旧列摘要；不执行迁移、不启动应用|
|`migrations-reference/`|三份SQL的原样审阅副本；正式执行仍用完整代码的迁移器，不能手工逐条粘贴|
|`SHA256SUMS.json`|交接包内容校验清单，不含自己或ZIP本身|
|`验证说明.md`|本交接脚本的隔离演练、拒绝路径及已知限制|

现有升级/备份程序都在完整代码的`scripts/lesson-maintenance/`。新后端首次启动自动执行迁移；请在它启动前完成备份和副本演练。不要把本地4187或`.local`的数据目录复制到服务器。

本次是1032–1034结构迁移及兼容回填，已有教材、学生、钱包和订单不重导；新课程包导入是部署后可选的内容录入，不是上线必做步骤。四主题素材随前端构建发布，不需要数据库素材导入脚本。

预检脚本要求显式`--app-root`和`--db`，复用完整应用的better-sqlite3，不加载应用/config/database，不读取密钥。输出只含结构、计数和哈希，仍应私有保存；正式库必须先识别实际路径与版本，预检通过不能代替副本升级演练。
