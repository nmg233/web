## 审核合入后的部署顺序（服务器负责人另行操作）

1. 锁定审核过的提交与锁文件；确认磁盘、Node及依赖版本，记录当前代码/数据库迁移号和服务配置。AI配置不作更改。
2. 暂停写入窗口，做SQLite一致性备份及附件/配置联合备份；核对manifest哈希、缺失引用、恢复副本。已有缺失文件单列，不补空文件伪造完整。
3. 在隔离副本先跑既有桥接/迁移，确认所有旧迁移号含义、schema1034、integrity_check、foreign_key_check及手工教材/报名/钱包/订单关键值。无误后才在备份保护下迁移正式库；启动代码会执行迁移，故不能先随意启动试错。
4. 后端与前端采用同一提交。依赖按锁文件安装，普通构建 `npm run build`；本地独立教学构建 `npm --prefix frontend run build -- --outDir ../build/mentor-teaching`。发布时由运维设置现有静态目录，不沿用开发用的本机端口。
5. 先验证管理员、导师学校权限、学生报名、教师观察、教材上传/旧版本、课程撤回；再使用明确测试样包验证导入。完成后人工清理/归档测试对象，不能删除真实学习历史。正式课程/礼品/价格只能人工核对录入。
6. 通知补投使用已有持久队列；未送达不回滚或重复创建业务对象。教学素材/数据库/凭据不进入代码Git仓库。

## 回退与恢复

迁移中断在事务内回滚，不执行手工删迁移行。升级后未写新数据可按窗口恢复联合备份+原代码；已发生新写入需先保全升级后快照，人工评估差异，不能直接恢复旧库丢掉新教学/订单。不要旧前端配新主题数据声称兼容；1034也不提供破坏式down迁移。

现成工具 `scripts/lesson-maintenance/backup.cjs` 与 `verify-backup.cjs` 支持联合备份、哈希验证、恢复到全新目录；具体CLI以其README及工具usage为准。`scripts/teaching.mjs backup --data <本地目录> --to <新目录>` / `restore --from <备份> --data <不存在目录>` 仅用于本地预览。恢复先改私有端口，不能启动副本占用现有服务。
