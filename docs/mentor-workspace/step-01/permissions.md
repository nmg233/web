# 范围、迁移及交接

新增1032迁移；已执行的1031及以前文件不变。新增课程学校范围、报名访问确认、历史教师学生目录、教师三元观察授权、教师创建记录、学生账号明确委托及审计。只有courses追加学校修订号，不重建旧课程、课时或账号。

|变化|新增操作|当前访问及历史|
|---|---|---|
|学校管理撤销|阻止该导师在此校建班、建号、调整上线/新增招生|独立课程管理不删除；合法有效报名学习保留；该导师授予的教师观察实时停止|
|课程管理撤销|该导师不能维护课程、招生、评审或履约|学校账号权限独立；原学生报名不自动取消；由该导师授予此课的教师观察停止|
|学校停用|不能新建账号、上线该校或新增招生|原课程/有效报名及教学历史保留；新式教师授权暂停，历史teacher_id已冻结关系保留原历史查阅|
|导师停用|旧会话及该导师范围操作失效|学生原合法报名保留；此导师授予的教师观察停止，管理员可明确接续授权|
|教师停用/改密|旧会话失效|授权和教学历史不删除，恢复后仍以当前关系核验，不扩大课程集合|
|学生转校|只有管理员按原迁校流程操作，先展示课程影响与保留说明|明确保留现有报名/学习；后续招生以新校范围核验；旧校观察因学校快照不符停止；管理员明确分配的新教师仅承接当前已有课程|
|课程学校缩小|预览受影响学生；有影响时必须管理员确认|只冻结具体报名ID以保留访问；不提供允许所有未来学生绕过校验的legacy开关|

新教师观察必须是明确的teacher×student×course，不使用teacher_id推导所有未来课程；来源为mentor的授权还核验授予者当前课程和学校权。管理员可独立授予或撤销，操作者保持真实admin身份。原teacher_id的目录关系和已有报名课程只在迁移时冻结，后续管理员明确分配只承接当时已有课程；不会因新课报名自动扩大观察。

课程已发布+学生有效报名仍是当前学生学习入口的原条件。本轮选择保留学校撤权、停用和转校前已有合法报名，不把招生范围当成删除教学历史的理由；要停止具体学习访问，管理员按原报名异常移除/课程归档规则操作，原数据和完成条件继续受保护。

## 服务器迁移顺序

本轮不部署服务器。代码经另行审核合入后：进入维护窗口 → 停止写入 → SQLite一致性备份+上传目录+私有配置联合保存 → 只读盘点课程、报名、学校和教师 → 运行既有版本化迁移 → 核对1032与完整性 → 管理员逐课明确上线学校 → 必要时明确委托组织学生和观察范围 → 前后端同步上线 → 验证后退出维护。不能只上传前端后继续运行旧权限后端。

迁移不推断整校招生授权：`course_school_scopes` 初始为空；`enrollment_access_confirmations` 仅按既有报名ID记录来源，`teacher_observation_grants` 仅冻结已有teacher_id和报名课程。旧课程仍可维护、学生原合法报名仍可用；新增招生须明确学校。不得清空迁移记录、改旧编号、重导课程或重写历史金币。
