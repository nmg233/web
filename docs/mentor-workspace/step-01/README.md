## 操作

1. 首次改密后进入导师“工作台”，可按课程、学校、报告、作品、礼品、课时准备、学校申请分类查看完整分页列表、总数和最后更新时间；刷新或重新聚焦会核对服务端。课程反馈/申请会话将在第二步接入，不把全平台反馈加入本步导师统计。
2. 学校与账号 → 学校申请与结果，填写学校、地区、用途及联系方式。批准前可备课，不能越权建班、建号或上线。同名学校须管理员明确核对。组织账号与观察页选择获准学校，建班、建student或固定teacher角色，私下交付有效初始凭据。首次登录强制改密，重复请求不重复建号，改密后的凭据不能再次导出。
3. 学生账号建立后仍未报名课程。导师只能维护本人创建或管理员明确委托的账号，同校不自动互看全部学生。管理员在账号与组织 → 学校办学账号中操作同一工具，并可明确委托/撤销学生账号维护；不自动授予学校、课程或角色管理权限。
4. 课程管理 → 新建课程草稿，保存后进入课程概览及填写清单。原六页签保持。学员与授权中明确选择上线学校、填写说明并保存，默认不勾全部学校；其他管理者的非本人学校范围保留。多人调整使用修订号，冲突后保留选择，先核对再保存。缩小范围会列出受影响学生，须管理员明确保留既有报名；不自动退课或删除历史。
5. 填写课时、上传文件、保存正文、受控预览，再分别进行课程发布、课时就绪、卡片发布。上传成功不代表正文已保存；学生学习后沿用原教材快照与版本保护。仅有学校上线不意味着全校学生自动报名；招生需课程管理、明确学校、导师学校和学生账号范围同时满足。
6. 配置教师观察时明确选择教师、学生和课程，填写原因。观察只限所选交集；学校、课程或导师停用/撤权后实时核对。教师不能建号、编辑教材、评审、发币或发奖；原teacher_id只冻结迁移时已有的学生与课程，不自动获得新课。
7. 教学与成长保留课程学生、报告、作品版本、任务、档案和反思。使用指引保留平台反馈、规则助手与实验等兼容入口；AI启用状态不变。
