## 二、默认预检

在部署仓库根目录运行，替换全部占位值：

```bash
node content/star-voyage/import-course.cjs \
  --db /目标数据库绝对路径/pbl_platform.db \
  --uploads /与后端UPLOAD_PATH一致的目录 \
  --assets /私有附件解压位置/private-assets \
  --admin-username '<目标环境有效管理员>'
```

默认仅检查：数据库已存在且具备所需结构、管理员有效且已改初始密码、课程包引用完整、图片签名/大小/SHA256一致、目标库没有待人工核对的同名课程。预期结果为 `dryRun:true`、`writes:0`、3课时/10槽位/9文件。

若数据库未升级，先按原部署流程迁移；工具不擅自迁移或初始化库。同名课程存在时停止核对，不能按名称猜测绑定，更不能删旧课后重导。

## 三、显式导入与结果核验

确认预检后，将上一步命令末尾增加 `--apply`。可以加 `--backup-dir /私有备份路径` 指定额外备份位置。

导入在 `BEGIN IMMEDIATE` 中创建新课程、课时、资源、地图、实验关联及徽章定义，并使用已有 `request_results` 保存包身份和结果。导入输出包含 `courseId`、`lessonIds`、`resourceIds`、新文件路径和备份路径，回执不要公开提交。

九张图片复制到目标uploads的独立 `resources/course-packages/<包指纹-唯一标识>/` 目录，通过原资源下载接口鉴权访问；不会公开静态暴露。原文章内图片引用会变成目标库新资源ID，课时和实验也重映射。原文不会改写。

导入后应核对：

- 课程为草稿，视觉主题 `voyage`、地图模式 `plan`。
- 三课时名称、类型、准备状态保持原样；后七个槽位没有伪造课时。
- 第一课八段文字与九张图片完整；无图片加载失败或跨课时引用。
- 第三课时滑翔机关联存在，独立实验仍可自由进入。
- 只导入徽章定义，没有授予徽章、金币或改变学习进度。
- 没有导入账号、报名、作品、报告、签到、订单、聊天或密钥。

正常异常会整体回滚数据库并清理本次新文件。文件系统和SQLite不共享崩溃事务：硬断电/强制结束进程可能留下未引用的独立目录；工具不会为了清理而删除未知文件。先核对备份、回执和资源引用，再由管理员处理孤立目录。

## 四、预览、发布与学生分配

1. 管理员打开 `/courses/<courseId>` → 课程内容维护 → 可视化填写/学生效果预览。
2. 依次核对三节课，查看第一课文章、图片、远航场景及十关地图配置。需要补充的教材继续使用原维护工具填写、上传和保存。
3. 当前三节课仍为准备中，七个关卡仍未配置；不要为了让按钮变亮而改成已完成或补造教材。
4. 审核后通过课程页面显式“发布”，再使用原“导入/分配学生”入口授予目标学生。导入脚本不会替管理员决定报名。
5. 学生从课程选择页进入新的星海课程，核对远航背景、三类场景、十关路线、角色入口及机器人。仅给旧校园课切换主题，不能替代课程教材导入。

课程发布和学生分配是运营环境写入，应由有权限的管理员按确认结果执行；本次PR与本机验证没有代为操作。

## 五、重复执行与回退

同一包重复执行返回 `alreadyImported:true` 和原ID，无新写入。即使换管理员执行，也不会再创建课程或附件。导入后人工改稿保留。修改同身份的包内容会被拒绝，应从既有维护页面继续修改，而不是覆盖重导。

如果导入尚未被学生使用，优先让课程保持草稿/归档并核对问题，不删除未知数据。需要整库恢复时先停服，确认导入后是否存在其他新业务写入；不能盲目用旧备份覆盖新作品或订单。使用既有恢复流程恢复到独立目录验证，再受控切换。导入额外备份只能覆盖它的时间点，不能代替后续增量数据处理。
