## 前提与部署

1. 核对当前部署 SHA 和实际数据库 schema。若还没有完成上一轮 1027/1028，先按原交接指南单独部署/迁移，本轮增量不能直接用于缺表的旧版。
2. 约定维护窗口，停止业务写入。使用原 `backup-only.cjs` 做 SQLite 与 uploads/反馈附件联合备份，再运行 `verify-backup.cjs` 校验；私有配置和应用版本另按运维流程保存。不要只复制运行中的主 DB。
3. 从自己的仓库取得本轮提交，在测试服务器先验证。原仓库 main 只读，本轮未提 PR、未部署生产。增量补丁基线为 `b3611dc`，若当前代码不同，先 `git apply --check` 或按正常 Git 合并审阅，不能盲目覆盖人工修改。
4. 沿用锁文件安装依赖，构建前端、部署构建产物并重启后端。后端增加了 `/student-copy/manage/:scope/sync`；新前端需要它，所以须同时更新。没有新增依赖或数据库初始化操作。
5. 管理员进入 `/student-copy`，用测试账号核对系统文字一次同步、教学侧栏保存、文章图片/附件、冲突与权限；另一个学生会话验证。确认 AI 仍关闭，原数据和上传保留。

系统文案立即发布到服务器，学生已打开页面最多 25 秒或聚焦时读取。文章和卡片遵循已有版本冻结：新进入学生适用当前内容，已绑定学生使用原快照。无需重建数据库、清空浏览器草稿或修改学生历史。

文章的现有 JSON 字段增加受校验的 `file` 附件块，引用已有本站资源，未增加数据库业务对象。若需回退旧代码，应先核对这些块的显示与编辑兼容性：旧代码可能不显示文件块，不能通过删除附件、清空正文或恢复整库来掩盖。回退不应覆盖维护窗口后新增的教学与学生业务数据。
